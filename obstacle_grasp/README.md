# obstacle_grasp — 障碍抓取族（分级场景）

和 `underwater_sampling` **同级、正交**的另一族：那一族考"**看不清**"（水体衰减、背向散射、低对比），
这一族考"**看不见 / 够不着 / 路被堵**"（遮挡、阻挡、窄缝、覆盖）。
**本包不做水下渲染**，不依赖 `underwater_vision`。

两族可以交叉组合：同一障碍场景换水况，就得到"障碍 × 能见度"的二维成功率矩阵。

- 设计依据：`../Lerobot-Uranus-VLA-Demo/docs/underwater_vla_task_design.md`
  的 §2.5（水下视觉难点第 4 条"自遮挡"）+ §3.1 任务族 + §3.6"每级必须有 `env.success()`"
- 复用底座：`Lerobot-Uranus-VLA-Demo/src/env_grasp.py` 的 6 自由度 IK、位置伺服残差闭环、
  夹爪宽度标定、慢速释放 —— 这些是拿血换来的，不重写

## 难度阶梯

| 级 | 名称 | 障碍物 | **新增的难度轴** | 判据 | 保持 |
|---|---|---|---|---|---|
| **O1** | 开阔基线 | 无（对照组） | 基线：视野与路径都通畅 | 方块落到圆盘上 + 夹爪张开 + 已落在台面 | 0.4s |
| **O2** | 视觉遮挡 | 相机与目标之间的立板 + 一个会动的干扰块 | **看得见但看不清**（实测遮挡率 65~68%）；路径仍通畅 | 同 O1 + **干扰块位移 <10mm** | 0.4s |
| **O3** | 前方低梁 | 目标 -x 侧、腕部高度的低梁（带两端立柱） | **路径阻挡**：默认姿态咬入 12.3mm，必须重新定向腕部 | 同 O1 | 0.4s |
| **O4** | 窄缝插取 | 两堵高 6cm 导墙，缝宽 6.5cm | **毫米级精度**：齿面外廓 5.52cm -> 每侧只剩 4.9mm | 同 O1 | 0.4s |
| **O5** | 覆盖堆叠 | 正压在目标上的另一块方块 | **长程 + 顺序**：不先搬开就抓不到目标 | 同 O1 | 0.4s |

**O1 是标尺**：O2~O5 与它的成功率差就是"加一个障碍要付多少代价"。整族**每级只加一个难度轴**，
所以任意两级之间的差值都能直接归因。

## 实测的几何约束（这些数字是量出来的，不是估的）

### O3 低梁确实挡住默认抓取走廊 —— 这一级是腕部自由度的用武之地

逐个俯仰角解 IK 到抓取位、`mj_forward` 后统计臂/爪与低梁的咬入深度：

| 腕部 pitch | 与低梁咬入 | 结果 |
|---|---|---|
| **+10°（默认抓取姿态）** | **12.3mm** | ✗ 撞梁 |
| 0° / -10° / -20° / -30° / -40° | 0.0mm | ✓ 通过 |
| +20° / +30° / +40° | 22.6 / 28.9 / 36.1mm | ✗ 撞梁（抬头更糟） |

**默认姿态过不去，把腕部俯仰压到 ≤0° 就完全让开** —— 而 0°~-40° 落在实测可达范围内
（pitch 限位 -50°~+55°，见 `underwater_sampling/README.md` 的腕部自由度一节）。
遥操作里按 `↓` 压低腕部即可。

### O2 的遮挡率是算出来再量出来的

立板高度不能拍脑袋：最初写顶高 0.46m，实测**把目标 100% 全挡**（藏掉目标一个像素都不变）——
那是盲抓，不是"部分遮挡"。按视线几何重取顶高 0.422m 后：

| 场景 | 目标完整轮廓 | 可见 | 遮挡率 |
|---|---|---|---|
| **O2（4 组随机布局）** | 233~270 px | 77~95 px | **64.8% / 66.4% / 67.0% / 67.7%** |
| **O1 对照（无立板）** | 233~260 px | 全部可见 | **0.0%** |

度量方法：四张图做差（`m_obj_full = |藏立板 - 都藏|`，`m_obj_visible = |正常 - 藏目标|`）。
O1 的 0% 同时验证了度量本身没写错。遮挡率随布局稳定（±1.5%），说明"障碍随目标一起随机化"这个
设计是对的。

### O4 的缝宽

齿面中心距 ±2.25cm + 齿厚半 0.51cm = 外廓 5.52cm；缝取 6.5cm -> **每侧余量 4.9mm**。
想调难度就改 `scenes/o4_narrow_slot.xml` 里槽壁的 `pos.y` 偏移（±0.0385 是半缝+半壁厚）。

## 文件

```
obstacle_grasp/
├── tasks.py      分级规格注册表（唯一真值表）：障碍物/难度轴/判据/指令池/布局随机化
├── env.py        ObstacleGraspEnv：分级加载 + 布局随机化（障碍随目标一起动）+ 判据
├── shots.py      拍摄展示：每级卡片 + 五级总览（纯 MuJoCo 渲染，不做水下处理）
├── scenes/
│   ├── _base.xml                 公共底座：工作台 + 机械臂（几何与现有抓取场景一致）
│   └── o1..o5_*.xml              五级场景
└── shots/        overview.png + 五张卡片
```

命名沿用底座：被操作物叫 `object`（带 `object_joint` / `object_geom`），目标点载体叫
`place_target`（带 `place_target_site`）。所以底座代码零改动，`get_obs()` 仍是 17 维。

**随机化**：目标与圆盘在现有抓取场景实测可用的范围内随机（x 1.555~1.645、y -0.10~0.12；
圆盘 y -0.18~0.04；两者至少隔开 10cm）。**障碍物随目标一起移动**，所以"障碍与目标的关系"
始终成立，难度不会因为随机化而漂移。

## 状态：哪些验证过了、哪些还没

**已验证（实测）**
- 五级场景全部加载、布局随机化、判据可跑、展示图可出

- O3 低梁对默认姿态的干涉 12.3mm，以及"pitch ≤ 0° 即通过"的解
- O4 缝宽 65.0mm vs 齿面外廓 55.2mm -> 每侧 4.9mm

**还没做**

  量出来的，应该固化成自检项 —— 这是下一步第一件事
- O3 / O4 / O5 的**整任务可解性**（不只是摆位不干涉）：需要一个把臂从待抓位送到抓取位再送到
  圆盘的过程检查，或者干脆先人手试跑几段
- `manual.py`：人手操作入口。可以直接复用 `underwater_sampling/manual.py` 的写法
  （子类化 `manual_collect.TeleopCollector`，覆写"怎么布置/怎么算完成/显示什么"），
  去掉水下渲染那部分即可

## 与水下族的关系

| | `underwater_sampling` | `obstacle_grasp` |
|---|---|---|
| 难度维 | 水况（能见度/颜色衰减/背向散射） | 几何（遮挡/阻挡/窄缝/堆叠） |
| 渲染 | 需要 `underwater_vision` 水下成像 | 纯 MuJoCo，不做任何后处理 |
| 任务族 | A 科学/生物采样（L1~L7）+ B 干预（L8） | O 障碍抓取（O1~O5） |
| 判据 | 多为几何量 + 接触力 | 沿用底座 `success` + 附加项（干扰块位移等） |

两族共享同一套 `UranusGraspEnv` 底座与命名约定，所以数据格式一致、可以混训。
