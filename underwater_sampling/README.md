# underwater_sampling — 水下采样任务族（分级场景）

给 UranUS 水下机械臂**人手采集**数据用的分级场景包：**七个从易到难的采样任务**，
每级只加一个难度轴，自带自动判据与语言指令池。

**本包不提供专家策略**（按需求：数据靠人手操作采集）。这里只负责三件事：
把场景搭出来、把随机化和判据配好、把"人力可解"验证清楚。

- 设计依据：`../Lerobot-Uranus-VLA-Demo/docs/underwater_vla_task_design.md` 的**族 A（科学/生物采样）**
  + §3.2 规格模板 + §3.3 课程 + §3.6"每级必须有 `env.success()`"
- 水下成像：`../underwater_vision`（人手操作时窗口里显示的就是水下图）

## 30 秒上手

```powershell
$env:PYTHONPATH = "E:\projects\mujoco\WYSD"      # 仓库根目录
cd E:\projects\mujoco\WYSD

python -m underwater_sampling.selftest                  # 117 项场景自检，退出码 0/1
python -m underwater_sampling.manual --list             # 打印难度阶梯
python -m underwater_sampling.manual --level l1_rock_collect --episodes 20
```

手动采集的操作键（沿用 `Lerobot-Uranus-VLA-Demo/manual_collect.py`）：

```

T 同布局重来   R 换新布局   Enter 保存本段   Backspace 放弃   Esc 退出
C 切换水下/清水渲染（默认按等级建议的水况显示水下图）
```

## 难度阶梯

| 级 | 名称 | **新增的难度轴** | 被操作物 | 目标 | 判据 | 保持 |
|---|---|---|---|---|---|---|
| **L1** | 抓取取样 | 基线（采样语义：托盘代替蓝盘） | 4cm 黄岩（高对比） | 采样托盘 | 进托盘 + 夹爪张开 | 0.4s |
| **L2** | 弱纹理 + 随机位姿 | **目标低对比**（灰岩 vs 沉积物底色）+ 位姿范围扩大 | 4cm 灰岩 | 采样托盘 | 同 L1 | 0.4s |
| **L3** | 双目标 + 语言指称 | **语言指称 + 干扰项** | 两块同色灰岩 | 采样托盘 | 指定目标进托盘 **且干扰项位移 <1cm** | 0.4s |
| **L4** | 易碎珊瑚轻取 | **窄目标（3cm）+ 软垫 + 不得翻倒** | 3×3×4cm 珊瑚 | 采样托盘 + 软垫 | 进托盘 + 未翻倒（倾角<25°）+ 夹爪张开 | 0.4s |
| **L5** | 推芯采样 | **工具夹持 + 竖直搬运 + 精密插入** | 采样管（r=2cm，竖立） | 取样座（导向井 8×8cm） | 管心到坐底位 <8mm + 管轴倾角 <8° | 1.0s |
| **L6** | 探针点测 | **mm 级对准 + 力上限 + 长保持** | 探针（针尖朝 +x） | 管壁测点（高 0.40m） | 针尖距测点 <8mm + 力 <12N | 2.0s |
| **L7** | 长程归位 | **多里程碑 + 归位** | 探针 | 测点 + 工具托板 | 拿起过 + 点测达标 + 回托板静置 + 夹爪张开 | 1.5s |

设计上**每级只动一个变量**，所以任意两级之间的成功率差可以直接归因。L1 是唯一能与现有
pick-place 基线对齐的等级；L1↔L2 的差值就是"定位变难"的代价（干净的消融对照）。

**水下不是等级，是正交的第二维**：每级都在 `underwater_vision` 的水况下跑
（`tasks.py` 的 `water` 字段给建议预设），于是能得到 **任务难度 × 能见度** 的二维成功率矩阵，
而不是一堆孤立数字。采集与评测**必须用同一组 `WaterParams`**（用 `WaterParams.hash()` 对齐）。

## 复用了什么、没重写什么

`SamplingEnv` 继承 `Lerobot-Uranus-VLA-Demo/src/env_grasp.py` 的 `UranusGraspEnv`，
**齿面中点 6 自由度 IK、位置伺服残差闭环、夹爪宽度标定（`align_jaws`/`grasp_angle`）、
慢速释放**全部沿用 —— 这些是拿血换来的，不重写。

命名约定也沿用底座：场景里被操作物一律叫 `object`（带 `object_joint` freejoint 和
`object_geom`），目标点载体一律叫 `place_target`（带 `place_target_site`），
**即使它实际是托盘 / 取样井 / 管壁立块 / 工具托板**。这样底座代码零改动。

`get_obs()` 仍是 **17 维**：`[关节(6), 物块相对齿面中点(3), 物块四元数(4), 目标相对齿面中点(3), 夹爪(1)]`。
所以 `build_frames` / LeRobot 管线 / 采集器都不需要改维度。L3 里**指令指定的目标才进 obs**，
干扰项不进 —— 逼策略靠图像+语言而不是状态里偷看。

## 实测的机械臂操作包线（这些约束决定了任务长什么样）

写场景时拿探针量出来的，直接决定"人能怎么做"，不是简化：

1. **腕部姿态固定**。遥操作只能平移齿面中点 + 开合夹爪；6 自由度 IK 把齿条钉成
   "长轴沿 x、下俯 10°"。所以**需要重新定向工具的任务做不了**（比如把平放的管子立起来）。
2. **`link6_mount` 是个 6cm 直径、9.7cm 长的圆柱**，其**下缘比齿面中点还低约 1.5cm**。
   于是容器壁越高，齿面中点就越下不去：实测 5cm 高的篮壁要到 z=0.415 才让开
   （0.375~0.410 全程啃壁，**咬入 17~19mm**）。
   → 所以托盘做成**内净 12.5cm、三面壁只有 2.5cm、朝机器人一侧开口**（ROV 采样筐的真实形态）。
3. **夹爪张开时两齿面间距 7.7cm**，齿面长轴还会被张开角转约 14°。
   → 任何高过托板面的挡边都会被齿面撞上，所以 L7 的工具架做成**平板**而不是凹槽。
4. **齿面中点 z 下限 0.365**（遥操作 LIMITS）、x ∈ [1.42, 1.80]。
   → L5 的"坐底"是靠"把竖立的管子搬到井口上方再下压"，不是靠把齿面伸到井底。
5. **夹持力峰值在 kN 量级且非单调**（轻合 squeeze=2mm → 5220N / 标称 4mm → 3801N /
   一夹到底 → 8139N）。位置伺服压进硬接触的瞬态尖峰主要取决于接触瞬间的相对速度，与
   squeeze 不成正比。**加上现有遥操作是二值夹爪（Space 开/合），操作者根本没有"更轻地合爪"
   这个动作** —— 所以 L4 原定的"力阈值判夹碎"被实测否掉，改成人力可控的"别碰倒"。
   力峰值仍逐拍记录在 `metrics()` 里，等给夹爪加了模拟量控制再启用。

## 判据怎么用

每级在 `tasks.py` 里给两个函数：

- `success(env)` —— **即时判据**（纯几何量：位置/倾角/针尖距离 + 接触力上限）；
- `settled(env)` —— "真的停稳了"判据（防止"举着样本从托盘上方经过"被误判成完成）。

采集器（`manual.py`）要求 `success() and settled()` **连续成立 `hold_s` 秒**才算完成
（`hold_s` 是每级的难度旋钮：L6 的 2s 就是"贴着测点稳住"）。**开局绝不判成功**已在自检里断言。

## 自检 = 替代"专家成功率标定"

按需求不做专家，所以"场景是不是人力可解"必须另找办法验证，否则浪费的是人的时间。
`selftest.py` 查五类共 **117 项**：

| 类别 | 查什么 |
|---|---|
| 加载 | 七级都能加载；底座需要的名字齐全；夹爪标定前提（x/y 延展相等）成立 |
| 随机化 | 抽 50 组：道具都在沉积物面之上、在台面范围内、互不重叠、离目标够远 |
| 物理静置 | 零控制跑 0.4s：不下沉/不弹飞/不发散；L5 的管子仍竖直 |
| **IK 可达** | 每级关键位姿（物块上方/物块处/目标上方/目标处/测点前方/工具架）解 IK 残差 <3mm |
| **摆位干涉** | 把臂摆到关键位姿后 forward，统计与静态道具的**咬入深度**（阈值 2mm） |

干涉判据用**咬入深度**而不是"有没有接触点"：实测齿面端部会在 0.1~0.2mm 量级贴住托盘
（接触生成的边界情形），而真正卡死的 `link6_mount↔篮壁` 是 17~19mm，差两个数量级。

```powershell
python -m underwater_sampling.selftest                       # 全部（约 1 分钟）
python -m underwater_sampling.selftest --levels l5_push_core # 单级
python -m underwater_sampling.selftest --no-physics          # 跳过物理静置，更快
```

自检还会打印两项**实测标定数据**（只记录、不作判据）：L4 的夹持力峰值对比、
L6/L7 的针尖可达 x 上限（当前 1.780 vs 测点 ~1.74，够得着）。

## 语言指令池

每级在 `tasks.py` 里配 **≥3 条训练模板 + 1 条 hold-out**；采集时逐段抽（75% 训练 / 25% hold-out），
写进 LeRobotDataset 的 `task` 字段 —— 同一个场景不同指令，数据里天然含"语言-行为"配对。

评测分两组报：**seen 指令**成功率 与 **unseen（hold-out）指令**成功率。掉得多说明语言泛化不行
（正常现象，但要量化）。L3 更硬：干扰项位移 >1cm 即失败，这是"语言分支到底有没有被用上"的
最小可判实验。

> ⚠️ **hold-out 句不要写进训练集**。当前实现是 75/25 混合抽样：**做正式消融实验时请把
> `instruction_split == "holdout"` 的段过滤掉再训练**（`env.layout["instruction_split"]`
> 与 `env.info()` 都能查到）。

## 数据预算与纪律（沿用设计文档）

| 场景 | 建议量 | 理由 |
|---|---|---|
| 单级（L1~L6） | ≥ 100~300 段 / ≥ 3~5 万帧 | 对齐现有 pick-place VLA 基线（300 段 / 50700 帧） |
| 多任务混训 | 每级 ≥ 50~100 段 | VLA 数据饥饿：1 任务 300 段 ≫ 10 任务各 30 段 |
| 消融对照（L1 清水/浑浊） | 两套各 ≥100 段，**同一 seed 序列** | 保证唯一变量是成像 |

**纪律**：不要为了"任务多"而摊薄每级数据量。宁可 3 级各 100 段。

## 已知限制

1. **没有专家策略**（按需求）。因此本包只能保证"场景人力可解"（IK 可达 + 无干涉 + 物理静置），
   **真实成功率必须来自实际的人工采集段**。第一轮建议每级先采 20 段，用
   `finish_episode` 打印的成功率反过来调难度旋钮。
2. **沉积物不做颗粒/接触建模**：L5 的"插入"是插进刚性导向井（真实工装），判据是几何量。
   底质力学、泥沙扬尘、水动力都在本项目范围外。
3. **L4 的"易碎"目前不是力阈值**（原因见上），只考"窄目标 + 别碰倒"。真正的力约束需要
   先给夹爪加模拟量控制。
4. **不做折射/焦散/体积光**：相机标定与几何会错位（对齐设计文档 §2.5）。
5. L3 的指称靠**立柱参照物**区分两块同色岩石；方位词（左/右）刻意没用 ——
   机器人视角的"左"容易有歧义，参照物更稳。
